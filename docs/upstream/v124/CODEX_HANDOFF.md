请接手我的 Nutug（nutug.cn）蒙古历史文化网站。GitHub 仓库是 https://github.com/Vles0123/nutug 。当前交付版本是 v124，日期 2026-10-07。仓库目前采用源码 ZIP 快照方式：先解压根目录 nutug-v124-source.zip，在解压出的 source 目录工作；旧 v20/v31 只是备份。不要把仓库根目录没有 package.json 误判为源码缺失。

首先读取 README.md、THIRD_PARTY_NOTICES.md 和本文件，检查实际目录和 Git 状态，运行 npm ci、npm run build、npm test，报告基线是否通过。没有获得新的具体开发目标时，先报告现状与待办，不自动批量重写或发布网站。

项目是原生 HTML/CSS/JavaScript 静态站，没有服务端、数据库或必需 API 密钥。dist/ 包含可部署页面及应用源代码，content/knowledge-data.js 是主知识库的唯一编辑源。知识库修改后通过 scripts/build-knowledge.cjs 重建分片和搜索索引；不要直接编辑 dist/knowledge/ 的生成结果。测试使用 jsdom 26.1.0；npm test 运行 28 个检查。npm run serve 可在本机 8080 端口预览。

交付基线：主知识库 1729 篇、1686 个规范化唯一来源 URL；人物图谱 32 人、53 条关系、18 事件；部落图谱 9 节点、16 边、3 个时期，另有 8 篇部落阅读。网站源提交是 1f11e44568d1b90837fac8d0e001bff52e53c932。不要把知识库文章数当作人物关系图规模。十万条是未来目标，压力测试用的是合成数据，不能宣称已实现十万条真实知识。

我的产品要求：
1. 传统蒙古文界面，数字用阿拉伯数字。要有蒙古文化特色，避免模板化设计。桌面与手机分别考虑布局，特别是竖排蒙古文、部落详情和黄历。
2. 内容宁缺毋滥，优先蒙古国网站和可靠一手资料，涵盖小众史实、部落、习俗、语言、游牧生活等；保留来源、地域、年代、争议与可信边界，不重复凑数，不将现代民族或部落关系硬套成血缘。
3. 保留精确词级正字法和显示变体。曾修正 edur/udur、baidal 的 i、bairi 多钩等问题。先检查 mongolian-orthography.js 及测试台账，不要全局替换字母或删除 FVS/MVS/ZWJ/ZWNJ/CGJ 等字符。文本必须保持整词塑形，搜索兼容已核验变体。
4. 图示放在对应知识条目里面，不另起栏目。目前有游牧四季、蒙古包搭建、马奶酒文化过程、蒙古袍部件、马头琴部件五个示例。游牧时间因地域年份而异，不能画成所有蒙古族通用固定日程。食品演示不能编造安全配方或功效。
5. 历史地图有 7 个时期、9 个近似锚点，自托管 Natural Earth 底图；移动路线为示意，勿假造精确边界。
6. 词语解释仅有少量词条，录音/TTS 暂时不做。下载按钮已按要求移除，不要恢复原始语料下载入口。
7. 当前黄历基于 lunar-javascript 1.7.7 的中国农历民俗体系，UTC+08、1901–2100，不是已获验证的蒙古传统黄历算法。节庆涉及年份和地区，逐年核实，不机械外推。

后续优先级：先保证现有版本可重复运行和字体/手机排版可靠，再按我的新指令修复问题、扩充有依据的内容。所有新增内容都检查来源是否直接支持、重复性、蒙古文字词和版权限制；保留原有测试与历史更正，不能简单改预期值使测试通过。已有批次之外的待写题材没有计入交付基线，应重新验证后再添加。

尚待确认：我曾说“成吉思汗的四个什么什么都加上”，具体是四杰还是四犬尚未确认，请先问清楚，不要按猜测添加。全站蒙古文母语校对和真实 iPhone/Safari 验收尚未完成；DOM 模拟测试只覆盖部分逻辑。现有云服务器迁移没有完成，GitHub 更新也不代表自动部署。

工作完成时给我：改动摘要、实际文章与来源数量、运行过的测试及结果、未验证项、修改文件、Git 提交号，以及需要时的部署说明。提交前检查无密钥、账户数据或原始受版权保护材料。未经我授权不要更改域名解析、采购服务器或发布新部署。
