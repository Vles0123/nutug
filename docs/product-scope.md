# 开发范围

Nutug 的主要用途是查看日历、按时间阅读历史，并从历史事件查看相关人物。界面使用中国境内规范传统蒙古文，沿用竖排、连写和蒙古文输入方式。

## 实施顺序

| 阶段               | 实现内容                                                                   | 完成依据                                                                 |
| ------------------ | -------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 共用底座           | 界面与资料分离、版本更新、离线读取、共用数据定义、字体与输入、日期引擎接口 | 同版使用缓存；新版可下载；中断后可继续读取旧内容；各入口能读取一致的数据 |
| 日历               | 普通月历、今日、选定日期、公历与传统历法对应                               | 日期换算、跨月跨年、时区和已选日期行为有依据；桌面与手机可操作           |
| 编年历史与人物关系 | 按年份与事件阅读，查看人物及关系                                           | 每条事件和关系有来源；时间精度明确；传统蒙古文完成编校                   |

日历沿用现有日期引擎适配层。现有引擎提供中国农历计算，地区节庆按资料中的年份和来源记录；后续确定传统历法规则后接入相应实现。

历史资料可从维基百科整理。保存原文页名、语言、页面与修订编号、获取日期和许可信息，再形成传统蒙古文条目。事件日期、时间范围与不确定性留在数据中，人物关系从事件与引用连接。

当前阶段维护共用底座。日历与编年界面的新设计按上述顺序推进。现有页面供开发和回归检查使用，产品导航在各主线实现时收拢。

## 当前进度

- 内容接口第 2 版采用版本号和普通 JSON 路径，网页按需缓存文章并支持完整离线保存。
- 生成端与网页共用内容数据定义，包含 ID、来源、目录与文档结构。
- 公历日期与现有农历引擎通过共用适配层访问，保留历法标识、时区和日期范围。
- 蒙古文排版与输入已接入网页；语言核查记录在 `ui-copy-review.json`，母语编校仍待完成。
- 原生应用与电子墨水屏的接入安排在共用接口稳定后实施。
