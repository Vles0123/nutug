# 代码评估

Nutug 已能支持小规模历史图谱、资料阅读和日历展示。数据与页面逻辑已有文件级分离，已有回归测试检查来源引用、人物关系和主要交互。继续扩展时，优先需要解决输入校验与键盘焦点问题，并减少渲染、手势、路由和状态之间的耦合。

评估日期：2026-10-03。

## 已复现的问题

### P2：人物深链接接受对象继承属性，导致渲染异常

- 位置：[人物 URL 处理](../public/app.js#L720)、[人物选择](../public/app.js#L334)。
- 复现：启动本地预览，访问 `http://127.0.0.1:8000/#person=constructor`。
- 实际结果：浏览器报告 `TypeError: Cannot read properties of undefined (reading '0')`，调用链为 `loadPersonFragment → choose → render → position`。选中状态先被改写，渲染随后中断，详情仍停留在原人物。
- 原因：`PEOPLE` 是普通对象，`if (PEOPLE[id])` 会把继承的 `constructor` 等属性当成人物记录；后续代码假设记录含有效坐标。
- 建议：在所有外部人物 ID 入口使用自有属性检查，并确认记录结构。无效 ID 应保持原状态或显示明确提示。补充 `constructor`、`__proto__`、不存在 ID 与正常人物 ID 的回归用例。

### P2：键盘激活图谱节点后丢失焦点

- 位置：[人物图谱节点](../public/app.js#L296)、[部落图谱渲染](../public/tribes.js#L223)。
- 复现：在人物页聚焦 `#graph [data-person="temujin"]` 后按 Enter；在部落桌面页聚焦 `#tribeGraph [data-tribe="temujin_following"]` 后按 Enter。
- 实际结果：两个页面完成选择后，`document.activeElement` 变为 `BODY`，键盘操作位置随节点重建而丢失。
- 原因：键盘处理调用选择函数，选择函数通过 `replaceChildren()` 重建 SVG，移除当前获得焦点的元素，焦点随元素移除回到文档。
- 影响：键盘用户失去操作位置，连续浏览图谱和辅助技术读取状态受到影响。
- 建议：保留节点 DOM，或在由键盘触发的重绘结束后按 ID 恢复焦点；同时覆盖人物、部落、关系边和研究空白节点。
